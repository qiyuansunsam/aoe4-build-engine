# Mathmatically Correct AoE 4 design

A neutral glass strategy workbench: luminous white over mist-grey in light mode, graphite over VS Code charcoal in dark mode. Translucent surfaces, restrained blue/amber comparison accents, fine rim-light and layered shadows restore the glass material without the previous green palette. Fraunces is reserved for major headings; IBM Plex Sans handles compact controls and IBM Plex Mono handles measures.

Comparison has two independent vertical columns: graph and object details on the left, a wide, readable status rail on the right. The rail ends with its content rather than stretching to the graph height. A single chart is also the timeline: distinct age, research, building, unit and Golden Age markers sit inside its canvas. Nearby events cluster behind a representative game icon and chevron, with a descriptive tooltip and an inline list retaining every action. Unexplained count markers are not used. The graph uses a fixed compact canvas with no collapse control. The metric picker exposes all supported measurements. The current time is editable and keyboard stepping is supported. There is no second timeline or range fader.

Each comparison slot shows the build name once in a custom dropdown, a path badge and its target time. All selects use one accessible listbox component with arrow-key navigation, Escape, focus restoration and preserved native change events. Routine details are inline rather than popup dialogs.

Villager, Camel Rider, Resources, Research and Spending are contextual objects selected through the comparison tracker. Selecting an A/B value supplies the active build context; no duplicate mode or path selector appears above details. Internal objects can be dragged into details or the chart. Details preserve the current chart; chart drops select the corresponding metric without changing time or object selection. The metric dropdown and object buttons retain keyboard alternatives. Individual food, wood, gold and stone income plus cumulative spending are supported chart metrics. Their content occupies the left column beneath the graph. Game portraits lead unit and technology choices. Upgrade previews add hypothetical historical-model effects while preserving the actual timeline and cost accounting; unsupported effects are explicitly distinguished. Provenance and assumptions live in disclosures, not repeated helper copy. Resource source allocations are labelled as workers rather than fabricated yield contributions.

At narrow widths the chart remains primary, the rail follows it and detail grids become two columns or stack. Reduced motion disables transitions. No ambient animation. Source identities remain separate: installed-build base facts, observed matches and historical theoretical simulations do not silently inherit each other's rules.

Material uses visibly translucent neutral surfaces over restrained blue-grey and warm-grey illumination. Fine highlights, soft shadows and blur distinguish glass from opaque white cards; text retains solid contrast. The status rail has no redundant legend or source footer. It provides readable A/B values with explicit numeric gutters, game icons, researched-tech count, per-resource income, and compact research status indicators with completed counts and active research progress. Villager details include actual worker allocations and food sources, not invented yield contributions. Reset and economic constraints live above the tracker in a compact disclosure. The opening hero and sidebar status/appearance labels are removed; the theme selector stands alone. The AI destination is named Crafter.

The graph now has a fixed compact 240px canvas. Expand/collapse and alternate timeline modes are removed; plotted data and event markers remain together.

Economic constraints and Reset live in a compact, non-draggable disclosure above the tracker, with independent A/B groups. Separate sidebar object navigation and active-build selectors are removed; selecting or dragging comparison rows supplies the detail context. The status rail contains only configurable metric rows, without separate income/research panels. Existing whole-build simulation parameters remain the baseline; scheduled timeline interventions are not implied by these controls.
