# Mathmatically Correct AoE 4 design

A neutral glass strategy workbench: luminous white over mist-grey in light mode, graphite over VS Code charcoal in dark mode. Translucent surfaces, restrained blue/amber comparison accents, fine rim-light and layered shadows restore the glass material without the previous green palette. Fraunces is reserved for major headings; IBM Plex Sans handles compact controls and IBM Plex Mono handles measures.

Comparison has two independent vertical columns: graph and object details on the left, a wide, readable status rail on the right. The rail ends with its content rather than stretching to the graph height. A single chart is also the timeline: distinct age, research, building, unit and Golden Age markers sit inside its canvas. Nearby events cluster behind a representative game icon and chevron, with a descriptive tooltip and an inline list retaining every action. Unexplained count markers are not used. The graph uses a fixed compact canvas with no collapse control. The metric picker exposes all supported measurements. The current time is editable and keyboard stepping is supported. There is no second timeline or range fader.

Each comparison slot shows the build name once in a custom dropdown, a path badge and its target time. All selects use one accessible listbox component with arrow-key navigation, Escape, focus restoration and preserved native change events. Routine details are inline rather than popup dialogs.

Villager, Camel Rider, Resources, Research and Spending are contextual objects selected through the comparison tracker. Selecting an A/B value supplies the active build context; no duplicate mode or path selector appears above details. Internal objects can be dragged into details or the chart. Details preserve the current chart; chart drops select the corresponding metric without changing time or object selection. The metric dropdown and object buttons retain keyboard alternatives. Individual food, wood, gold and stone income plus cumulative spending are supported chart metrics. Their content occupies the left column beneath the graph. Game portraits lead unit and technology choices. Upgrade previews add hypothetical historical-model effects while preserving the actual timeline and cost accounting; unsupported effects are explicitly distinguished. Provenance and assumptions live in disclosures, not repeated helper copy. Resource source allocations are labelled as workers rather than fabricated yield contributions.

At narrow widths the chart remains primary, the rail follows it and detail grids become two columns or stack. Reduced motion disables transitions. No ambient animation. Source identities remain separate: installed-build base facts, observed matches and historical theoretical simulations do not silently inherit each other's rules.

Material uses visibly translucent neutral surfaces over restrained blue-grey and warm-grey illumination. Fine highlights, soft shadows and blur distinguish glass from opaque white cards; text retains solid contrast. The status rail has no redundant legend or source footer. It provides readable A/B values with explicit numeric gutters, game icons, researched-tech count, per-resource income, and compact research status indicators with completed counts and active research progress. Villager details include actual worker allocations and food sources, not invented yield contributions. Reset and economic constraints live above the tracker in a compact disclosure. The opening hero and sidebar status/appearance labels are removed; the theme selector stands alone. The AI destination is named Crafter.

The graph now has a fixed compact 240px canvas. Expand/collapse and alternate timeline modes are removed; plotted data and event markers remain together.

Economic constraints and Reset live in a compact, non-draggable disclosure above the tracker, with independent A/B groups. Separate sidebar object navigation and active-build selectors are removed; selecting or dragging comparison rows supplies the detail context. The status rail contains only configurable metric rows, without separate income/research panels. Existing whole-build simulation parameters remain the baseline; scheduled timeline interventions are not implied by these controls.

## Library and build reading

Navigation is Comparison, Builds, Games, Library, Crafter and Guide. Games contains recorded matches; Library contains unit/civilization records. Legacy game/database deep links remain valid. Lists use compact filters rather than hero headings or descriptive banners. Every civilization has its exact game flag. Object names are plain selectable links, with blueprint identifiers confined to source evidence.

Builds are filterable by patch, civilization and evidence type. Each build opens a single-path timeline with real model or recorded snapshots, event icons, a time cursor and selected-time details. Preview state never mutates the two comparison slots. Historical theory remains16.2.10604; recorded11308 labels normalize to16.3.11308.

The data patch picker separates installed base values from announced17.0 changes. Preview rows only show audited deltas; they do not imply a complete upcoming ruleset. Opening a preview record retains an explicit installed-baseline heading plus its announced changes. Game rows use map/civilization identity and Pending review/Build crafted tags tied to draft acceptance.

Crafter uses two aligned glass panels with operational status and form labels, no empty explanatory prose. Guide contains task-oriented instructions and expandable source/model limits.

Simulation constraints sit above the tracker in the right column, with independent A/B disclosures. These configure idle fraction, resource travel distances and drop-off delay, not production buildings or age-up choices. Optional timed villager attrition affects the economy and replacement production; it is not a combat model. Unit upgrade tiles show actual selected-time research progress, separately from hypothetical preview toggles.

Navigation separates Library (civilization-first catalog, searchable units and patch filters) from Games (recorded matches, with All games and Build crafted views). AoE IV is the prominent text brand, without a monogram. Build selectors have search. Build/object context menus offer local per-build comments and a new-tab action.

Build pages lead with the ordered action log and selected-time worker split. Model actions include construction, production and research; recorded actions retain source timing and do not invent missing orders. Outcomes are a collapsed secondary disclosure. Games create local pending reference drafts in Builds; explicit acceptance makes them selectable and marks their source game Build crafted. Worker splits absent from recorded data are shown as a labelled income-share estimate.

Library records prioritize base statistics, actual training/research buildings, grouped upgrades and relevant patch changes. Technical source hashes, blueprint JSON and requirement internals stay out of the product detail view. Unit tiers collapse into families, with searchable gameplay tags and producer filters. Current/Next is a compact toggle; announced deltas remain distinct from installed base values. Comparison upgrade previews use the historical model research-building groups.

Civilization rosters group compact unit rows by their primary production building. The list has no tier expander or tier count; individual unit details retain tier information. Units with multiple production sources appear once under a conventional production building, while their detail page retains all source links.

Games is one collection without All/Build-crafted tabs. Each online match supports selecting civilization/player, downloading its AoE4 World timeline, and creating a pending build; review stays in Builds. Build timelines highlight milestones and collapse routine actions into counted time ranges. A selected-snapshot resource tracker shows bank, income and spending beside the order, with recorded/model labels.


Build timelines now use three columns: actions started, completed production, and a resource sidebar. All worker allocation lives in the sidebar. Routine actions are grouped into expandable time ranges; starts and completions are never mixed. Recorded games list recorded completions in the Completed column and inferred starts (completion minus installed base duration) in the Actions column, each labelled; the worker split is a labelled estimate. Resource-site construction and completed-worker accounting are modeled before gathering begins.


Game details load the actual saved AoE4 World match summary, fetching it automatically on first open when needed. The summary supplies player scores, APM, resource histories and recorded build completions. Games list text is larger, rank labels are numeric, and download-status prose is omitted. Failed downloads offer retry without a repeated request loop.


Player search queries AoE4 World on demand. A selected profile becomes a removable exact-ID player tag; clicking an existing player name chooses that ID directly. Tagged results load that profile's paginated games with alternate accounts excluded, while untagged text can still filter the saved collection. Provider lookups are bounded and cached, and fetched match metadata preserves existing downloaded perspectives.


Summary team headers identify the winning side from recorded results. Player names inside a match select and focus that player's recorded build order; Games-list names still select an exact search tag. The recorded order has its own selected-player crafting action. Army details use horizontal unit/icon/count tabs and expose non-Abbasid installed stats and building-grouped upgrades. Comparison value markers stay within their source timelines; gathered histories are derived as bank plus spending minus the starting bank, labelled "derived", never by relabelling the provider's spending-like fields.


Comparison choices follow available data. A saved metric unavailable for both slots falls back to a supported comparison, and unsupported tracker rows/options are omitted. Partial availability is labelled per path. Observed unit panels select a catalog record immediately and use exact record icons; unavailable army-value cards are omitted.


Observed army value is a labelled base-cost estimate: recorded unit balances multiplied by installed catalog food/wood/gold/stone costs. Each unit exposes count, cost per unit and subtotal; unknown costs remain unknown. The tracker also exposes individual units directly. These values do not imply tier-transition, conversion, discount or live army reconstruction.


Recorded builds are complete in the comparison: population, gathered resources, army value, Town Centers, farms, military units, villager losses and Camel Riders are derived at view time from recorded completions, losses, bank and spending multiplied by installed catalog facts, and every such row carries an estimate/derived suffix. The same derivation runs for lazily loaded perspectives and for reference drafts crafted from Games, so Abbasid-to-Abbasid, Abbasid-to-recorded and recorded-to-recorded comparisons expose the same metric set, tracker rows, villager economy panel (income, bank, derived gathered, estimated split, losses), research ledger with inferred research progress and upgrade tiles with recorded or inferred status. Chart event rows follow slot order: path A sits nearest the plot, path B below it. The build page sidebar leads with population, villagers, army value and researched counts and its Expected graph exposes every supported metric.
